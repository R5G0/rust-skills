# perf-ahash

> Change hashers only after measuring the workload and evaluating attacker control of keys

## Why It Matters

The standard HashMap uses a randomized hasher designed to resist hash flooding; its exact algorithm is not a stable guarantee. A different hasher can reduce costs in some map-heavy workloads, but changes collision behavior, dependencies, and the security assumptions of the map. Key length, CPU features, entropy configuration, and input provenance all matter more than a generic speed ratio.

## Bad

```rust
use rustc_hash::FxHashMap;

// Request-controlled names can be chosen to exploit a predictable hasher.
pub fn count_public_names(names: &[String]) -> FxHashMap<String, usize> {
    let mut counts = FxHashMap::default();
    for name in names {
        *counts.entry(name.clone()).or_insert(0) += 1;
    }
    counts
}
```

## Good

Retain the standard default for externally controlled keys unless a concrete alternative's security properties justify changing it:

```rust
use std::collections::HashMap;

pub fn count_public_names(names: &[String]) -> HashMap<String, usize> {
    let mut counts = HashMap::with_capacity(names.len());
    for name in names {
        *counts.entry(name.clone()).or_insert(0) += 1;
    }
    counts
}
```

For a measured internal workload whose keys are generated by trusted code, a specialized hasher can be appropriate:

```rust
use rustc_hash::FxHashMap;

pub fn build_internal_nodes(nodes: &[(u32, String)]) -> FxHashMap<u32, String> {
    let mut map = FxHashMap::with_capacity_and_hasher(
        nodes.len(),
        Default::default(),
    );
    map.extend(nodes.iter().cloned());
    map
}
```

## Key Points

- Benchmark representative key distributions and map operations; no hasher is universally fastest.
- Integer keys are not automatically trusted. Check whether external inputs can select or influence them.
- AHash is a keyed, randomized candidate; its entropy source and constructor matter. A fixed seed is not equivalent to a randomly seeded map, and AHash is not a cryptographic digest.
- Keep the standard default when there is no measured reason to add a dependency or change collision behavior.
- Preserve the Hash/Eq contract: equal keys must produce equal hashes.
- Changing a public concrete map type can affect callers. Do not assume a replacement is API-compatible merely because common methods look similar.
- Independently bound input size and work where overload matters; randomized hashing is not a complete denial-of-service defense.
